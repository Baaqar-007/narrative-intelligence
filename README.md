# NIE — Narrative Intelligence Engine

A temporal, graph-augmented retrieval system for fictional narratives, developed
as an original research project. NIE builds a knowledge graph of characters,
places and relationships from public-domain novels, adds a narrative-position
(temporal) layer, and answers questions with **graph-verified, cited facts**.
The language model only phrases the answer; it never decides what is true.

NIE is built on the **Artificial Relationships in Fiction (ARF)** dataset, which
already provides entities and relationships for 96 books. The project does not
perform relation extraction. Its work is graph construction, retrieval,
grounded question answering, and (in progress) entity resolution and
counterfactual simulation.

## Status

## Design principles

- **Dataset-first.** For books in ARF, the dataset's entities and relations are the
  source of truth. No relation extraction, no model training, and the LLM never
  invents graph structure.
- **The LLM phrases; it does not reason.** The answer prompt forbids chaining
  facts into unsupported conclusions. Simulation will be graph-algorithmic, with
  the LLM only narrating computed results.
- **Non-destructive layers.** The raw graph is never mutated; filters and
  resolution live in separate maps that retrieval opts into.
- **Measure, then build.** No new framework or complexity before a measured need,
  and no week is "done" on passing tests alone.

## How it works

```
ARF dataset -> entity canonicalization -> knowledge graph (per-book MultiDiGraph)
            -> temporal layer (narrative-position bins)
            -> relation-level embeddings (ChromaDB)
            -> hybrid retrieval: vector search -> graph enrichment
                 -> query-direction detection -> chain expansion -> resolution layer
            -> LLM phrasing -> cited answer
```

Questions it is built to answer include single facts ("Who is the protector of
Taug?"), direction-sensitive ones ("who protects Taug" versus "who does Taug
protect"), multi-hop chains ("who is the enemy of the companion of Taug"), and
narrative-position queries. Design rationale and rejected alternatives are in
[`docs/architecture.md`](docs/architecture.md).

**Stack:** Python 3.12, pandas, NetworkX, NumPy, Sentence Transformers, ChromaDB,
FastAPI, Docker, Groq (LLM step).

## Quickstart

```bash
python -m venv .venv
source .venv/bin/activate        # macOS/Linux
# .venv\Scripts\activate         # Windows (CMD)
# .venv\Scripts\Activate.ps1     # Windows (PowerShell)

pip install -r requirements.txt
pip install -e .
```

`requirements.txt` is the slim, deploy-only set; `requirements-dev.txt` is the
full local environment.

Run the tests:

```bash
python -m pytest tests/ -v
```

Build the data pipeline (graph, embeddings, vector store), then run the
benchmarks. Run both from the repository root:

```bash
python -m scripts.build_pipeline
python -m scripts.run_benchmarks
```

`data/` and `model_cache/` are git-ignored and fully regenerated by the build
pipeline. Building the embeddings for the full corpus takes on the order of 20
minutes on CPU.

## Running the API and demo

The service needs a Groq API key (`GROQ_API_KEY`).

```bash
docker build -t nie-api:local .
docker run -p 7860:7860 -e GROQ_API_KEY=your_key nie-api:local
```

The app serves a single-page frontend at `/` and three endpoints: `GET /health`,
`GET /books`, and `POST /query` (a book id and a question in; an answer and cited
sources out, with `chunk_id` provenance for each fact). Hosting options and the
reasoning behind the self-hosted approach are in
[`docs/deployment.md`](docs/deployment.md).

## Results at a glance

Measurements come from two generations of evaluation that are **not
interchangeable**; read [`docs/benchmarks.md`](docs/benchmarks.md) before
quoting any number.

| Measure | Result |
|---|---|
| **v2 correctness yardstick** (current code, no resolution maps; 5,115 structured questions) | HIT 38.0%, DECLINED 48.6%, WRONG 13.4%; 22.3% of questions whose returned answers are all correct (precision 1.0) |
| Resolution layer on the same yardstick (before a later fix, which is unmeasured) | HIT 29.1% strict / 34.2% canonicalized scoring; WRONG 24.4% / 19.3% |
| v1 single-hop direction-aware accuracy, hybrid retrieval, k = 1 to 20 | 34.0% rising to 80.0% (historical; validity not re-established after a later question-generator fix) |
| Narrative activity across the corpus | 89 of 95 books distribute relational activity roughly evenly (weighted mean position 0.4–0.6; corpus mean 0.531) |
| Entity-name noise | 22.4% of 1,298 parent-lookup frontiers resolve to more than one candidate node, the largest category is pronoun and generic names (47.1%) |

Earlier v1 multi-hop figures (72% versus 26%) are **void**: the traversal side
turned out to be a self-consistency check. The yardstick is the current end-to-end
measure, and its figures describe the live system as it stands, including its
failures.

## Known limitations (summary)

- Generic and collective entities (`"apes"` versus `"the apes"`) and true aliases
  (`Tarzan` versus `Lord Greystoke`) are not resolved.
- ARF's labels contain noise (direction inconsistencies, contradictory
  parentage edges, mistagged types). It is documented and scoped around, not
  silently corrected.
- Multi-hop retrieval is live but limited, and the entity-resolution layer
  currently lowers end-to-end accuracy.
- The answer step can pass source contradictions to the LLM unflagged.

The full list, with status, is in
[`docs/known-limitations.md`](docs/known-limitations.md).

## Data and attribution

The corpus is the ARF dataset (Hugging Face `Despina/project_gutenberg`, config
`synthetic_relations_in_fiction_books`): 95,476 chunk-level rows across 96 books,
with 128,331 GPT-4o-extracted relation instances over an 11-type entity ontology
and a 48-type relation ontology. See Christou and Tsoumakas, *Artificial
Relationships in Fiction: A Dataset for Advancing NLP in Literary Domains*
(LaTeCH-CLfL 2025). The underlying texts are public-domain works from Project
Gutenberg. Because the relations are model-generated, they carry the noise noted
above; NIE reports results against the graph as stored, not against real-world
truth.
